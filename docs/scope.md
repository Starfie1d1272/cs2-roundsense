# RoundSense — Scope

> 状态：v0.1 研究基线（2026-08-06）
> 本文件固定"当前做什么、明确不做什么"。任何超出本文件范围的改动须先改本文档。

## 1. 项目定位

面向 **CS2 普通玩家**（非观战/非赛事制作）的**只读实时决策辅助研究项目**。不是通用 HUD、不是直播工具、不是 OBS 套件、不是游戏内 Overlay。

本轮目标是建立**可验证的研究基础**，优先验证两项能力：

1. **P0-A**：普通玩家状态下 C4 安放事件读取与剩余时间估算的精度（在不明显增加延迟/不稳定性的前提下）。
2. **P0-B**：基于个人经济、装备与下一回合目标，给出简明、可解释的购买建议（目标约束型购买规划器，不是金钱显示，也不是经济表格）。

## 2. 数据来源边界（本阶段唯一允许的信号源）

| 来源 | 用途 | 状态 |
|---|---|---|
| GSI（本地 HTTP POST，127.0.0.1） | 实时决策输入 | P0-A/P0-B 输入 |
| `cs2-demo-format` v3 ZIP（本地） | 真值分析、离线验证 | P1（adapter + 抽样验证） |
| 社区/官方文档 | 规则来源（版本化引用） | 仅文档 |

**明确禁止的信号源**：游戏内存读取、DLL 注入、DirectX/Vulkan Hook、OCR、屏幕捕获、网络抓包（非本机 GSI 之外）。

## 3. 当前范围（P0/P1/P2）

### P0-A：C4 时间估算研究

- 最小 GSI 接收器（只监听 127.0.0.1、token 校验、关键路径尽快 204、不记录 auth、原始载荷 NDJSON 落盘、双时钟记录）。
- C4 状态机（重复 payload 去重、中途启动只建基线、缺中间状态不伪造、重启安全重置）。
- 剩余时间估算器（基于单调时钟 + 版本化引信规则；**不把 40s 当作普适事实**，规则文件注明来源与核验状态）。
- Windows 实验协议（本地服务器重复安放、demo 回放、真实竞技/Premier、buffer/throttle 矩阵、demo tick 对齐、延迟/抖动/漏报/重复率指标）。

### P0-B：个人经济与购买决策

- 领域输入/输出类型、经济情景计算接口、候选购买组合接口、可解释建议的数据结构。
- 规则版本化方案（奖励/价格全部来自版本化规则文件，注明来源、核验日期、适用模式）。
- 少量已知情景的单元测试。
- **不重新实现完整经济账本**：账本与真值来自 `cs2-demo-format` 的 `player-economies.json` 与 DAK 分析层；本模块只做"规划器"。

### P1：数据真值与回放框架

- `cs2-demo-format` v3 ZIP 的只读 adapter（路径可配置，不绑定绝对路径）。
- 明确 rounds / bombs / kills / player-economies / 装备 中哪些字段可作为 C4 与经济真值；时间单位；玩家-回合-阵营关联；缺失字段显式报告，不静默猜测。
- 回放 harness：脱敏 GSI fixture 在 Mac 上确定性回放，测试状态归一化/差分/C4 状态机/去重/缺包乱序/重启/经济情景计算。
- 批处理接口只设计不批量执行（300+ 场语料位置待用户提供路径）。

### P2：敌方经济（仅研究方向记录，本轮不实现）

普通玩家缺少敌方精确购买/存枪/发枪/拾枪/击杀武器奖励信息。未来输出只能是：Eco/Force/Half/Full 概率、团队经济范围、主要不确定性、低置信度自动隐藏。**不实现敌方精确金额，不把不可观测变量填默认值。**

## 4. 明确不做（本阶段）

- 通用比分/血量/弹药/装备 HUD；手机 PWA；Electron/Tauri/WinUI/WPF 桌面壳；Overlay；安装器/自动更新；云端同步；OBS/直播模式；OCR；内存读取；注入/Hook；自动购买/按键/鼠标/输入控制；敌方位置/雷达/投掷物轨迹；复杂机器学习模型；无需求支撑的数据库/Docker/消息队列/微服务。
- 允许最小调试 CLI（观察原始状态、C4 估算、经济建议），不演变为通用 HUD。

## 5. 仓库边界与流程约束

- 只读检查已有仓库（cs2-demo-format、cs2-demo-analysis-kit 等）；新代码全部在本仓库。
- 不批量处理全部数据；只验证少量代表性 ZIP。
- 未经验证的结论必须标记"假设/待验证"；区分 GSI 直接观测 / 状态差分推导 / 规则估算 / demo 真值。
- 跨平台纯逻辑；Windows 特有代码与路径隔离（`apps/gsi-recorder` 的 cfg 生成与实验脚本为 Windows 侧，标注清楚）。
- 默认 local-first，不上传原始游戏数据。
- Conventional Commits；不添加 `Co-Authored-By`。
- 不创建公开远程仓库、不推送，除非用户明确授权。

## 6. 验收（v0.1）

- [x] 仓库可在 Mac 安装依赖、构建、跑测试
- [x] 最小 HTTP receiver 接收 fixture、校验 token、快速 204
- [x] NDJSON 同时保存墙钟与单调时钟接收时间
- [x] 相同 fixture 多次回放结果一致（确定性）
- [x] 重复 planted payload 只生成一次安放事件
- [x] 跳过中间状态不伪造精确事件
- [x] 重启后首包不误判为新安放
- [x] 经济情景计算为纯函数并有单元测试
- [x] 经济数值来自版本化规则文件
- [x] demo adapter 读取至少一个代表性 ZIP 的回合/炸弹/经济数据，或明确报告缺失
- [x] Windows 第一轮 C4 实验步骤文档
- [x] 未实现"不做"范围
- [x] 文档区分 已证实 / 代码暂定 / 待 Windows 实测 / 未来研究
